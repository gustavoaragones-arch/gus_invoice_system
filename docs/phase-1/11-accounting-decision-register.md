# 11 — Accounting Decision Register

Status: Draft for Project Director review
Phase: 1

Formal register of every accounting/billing decision established in Phase 1. IDs are stable and must not be renumbered once accepted. "Professional Confirmation Required" = Yes means the decision, while implementable now, should be confirmed against real business/tax facts by the owner/accountant before being relied upon for a real, live business. Status is `Proposed` for every entry in this document — only the Project Director can change status to `Accepted`.

## Open / Unresolved Items Surfaced During Phase 1

These could not be safely resolved within Phase 1's authority and remain open, consistent with Phase 0's own unresolved-decision framework:

- **Business A historical numbering reconciliation** (referenced in DEC-INV-003, DEC-INV-009, DEC-HIST-005) — requires Business A's actual historical numbering pattern (Phase 0 UD-DATA-003), not yet available.
- **Fiscal-year vs. calendar-year YTD reporting** (DEC-ACC-002) — only relevant if the business's fiscal year differs from the calendar year; no Phase 0 requirement indicates this is needed, so it is not built, but flagged in case it is.
- **Tax calculation sequence and rounding convention professional confirmation** (DEC-TAX-002, DEC-MONEY-003) — a defensible default is defined and used consistently, but requires accountant sign-off before being relied on for real filings.
- **Zero-rated / exempt service classification** — structurally supported ([07-tax-and-pricing-rules.md](07-tax-and-pricing-rules.md) Sections 5-6), but which specific services (if any) qualify is not decided, and cannot be, without accountant confirmation.
- **Period attribution for corrected invoices** (DEC-INV-008) — the system reports a replacement invoice in its own period, not backdated; confirmed acceptable to the business's accounting practice or not, is outside Phase 1's authority.

No Phase 0 contradiction was identified during Phase 1 (see [12-phase-1-summary.md](12-phase-1-summary.md), Cross-Document Validation) — the items above are gaps requiring further input, not conflicts within the governing baseline.
